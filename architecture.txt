To build a zero-cost, fully automated, and resilient job aggregation engine, the architecture relies on GitHub Actions for free scheduled compute, Google Gemini 1.5 Pro (via the free-tier Google AI Studio API) for intelligent tailoring, and Google Workspace (Sheets and Drive) for persistent state and file hosting.

This ecosystem ensures your pipeline runs continuously, handles failures gracefully without crashing, and organizes tailored application assets into a single master dashboard.

## Zero-Cost Technology Stack

* **Orchestration & Compute:** GitHub Actions. A workflow file configured with a cron schedule (`cron: '30 11,17 * * *'` for UTC equivalent of 6:30 AM and 12:30 PM CDT) triggers the Python engine twice daily. This operates entirely within GitHub's free compute tier.
* **AI Engine:** Google Gemini 1.5 Pro API. Handles the heavy lifting of evaluating Job Descriptions (JDs), mapping ATS personas (e.g., Workday, Greenhouse), and rewriting the base LaTeX code.


* **Compilation:** A lightweight LaTeX distribution (`texlive-latex-base`) installed directly on the GitHub Actions Ubuntu runner to compile PDFs on the fly.
* **Storage & Persistence:** Google Sheets API (`gspread`) serves as the master database, preserving historical data across runs. Google Drive API (`PyDrive2` or `google-api-python-client`) hosts the generated PDFs.

## Step-by-Step Resilient Operational Flow

### 1. Ingestion & Filtering

The Python engine queries the zero-bot-hurdle data sources: the specific GitHub repositories (jobright-ai, SimplifyJobs, speedyapply, zapplyjobs), RSS feeds like We Work Remotely, and direct JSON ATS endpoints.

* **Role Match:** The script filters for Intern, Trainee, Co-op, and specific titles (DevOps, SRE, Cloud Engineer, Data Analyst, Data Engineer, Product Manager, MLOps, DataOps, Technical Sales, SWE).


* **Seniority:** It parses the text to exclude roles requiring more than 4 years of experience.


* **Exclusions:** Any job containing "Marketing" or "Sales Analyst" is instantly dropped.


* **Location Sorting:** The filtered list is sorted by prioritizing Texas (Dallas/Richardson) first, US Remote second, and other US locations third.



### 2. Deduplication via Google Sheets

Before initiating any heavy API calls or scraping, the script authenticates with the Google Sheets API.

* It pulls down the "Job link" and "Job title" columns to create a local set of already-processed jobs.


* If the exact URL exists, the script skips the job entirely, ensuring you never process or evaluate the same link twice.



### 3. Tiered Job Description Extraction

To avoid triggering bot detection, the script employs a tiered extraction strategy:

* **Tier 1 (Zero-Hurdle):** Attempts to pull from Greenhouse, Lever, or Ashby public JSON endpoints using standard `requests.get()`.


* **Tier 2 (Standard HTML):** Uses `BeautifulSoup` to parse standard, unprotected job boards.
* **Tier 3 (Headless Browser - Last Resort):** If required, it spins up Playwright to render JavaScript for protected sites.

### 4. Gemini ATS Tailoring

For successfully extracted JDs, the script identifies the ATS platform from the URL (e.g., `.myworkdayjobs.com` for Workday, `boards.greenhouse.io` for Greenhouse).

* It selects the correct base LaTeX template (e.g., DevOps, Data Analyst, SWE) based on the job title.


* It sends a prompt to Gemini 1.5 Pro containing the JD, the ATS persona instructions (e.g., Workday optimization rules, Greenhouse parsing), and the base LaTeX.


* Gemini returns two clean LaTeX strings: the tailored resume and the tailored cover letter.



### 5. Document Compilation & Cloud Upload

* The script saves Gemini's output as `.tex` files on the GitHub runner.
* It executes `pdflatex` to compile both the resume and cover letter.
* The resulting PDFs are uploaded to a specific Google Drive folder via API, with permissions set so anyone with the link can view them.

### 6. Master Sheet Update

The script appends a new row to the Google Sheet, writing the timestamp, location, and generated Google Drive links. The run concludes, and the GitHub Action spins down.

## Google Sheets Architecture

Your single Master Google Sheet will act as a persistent, append-only database.

**Required Column Mapping:**

1. **Timestamp:** Date and time of the run (e.g., 2026-11-06 06:30:00 CDT).
2. **Job Title:** The extracted role name.


3. **Location:** To confirm Texas/Remote status.
4. **Job Link:** The direct application URL.


5. **Extracted Job Description:** A snippet or the full JD text.


6. **Tailored Resume PDF:** The Google Drive link to the compiled PDF.


7. **Resume LaTeX Template:** The raw code generated by Gemini.


8. **Tailored Cover Letter PDF:** The Google Drive link to the compiled PDF.


9. **Cover Letter LaTeX Template:** The raw code generated by Gemini.


10. **Status:** Defaults to "Not Applied". You will update this manually.

## Strict Guardrails and Fallback Mechanisms

To ensure the application runs smoothly without halting on unexpected errors, independent `try/except` blocks govern each critical phase.

**Extraction Fallback:**
If Tier 1 through Tier 3 extraction methods fail due to aggressive bot protection (like Cloudflare blocks), the script catches the timeout. Instead of exiting, it logs the job into the Google Sheet with the Job Link intact, fills the Extracted Job Description column with *"Unable to extract job listing"*, leaves the PDF columns blank, and immediately moves to the next job in the queue.

**Gemini AI Fallback:**
If the Gemini API times out or returns a severely malformed response that strips the LaTeX formatting, the script catches the error. It bypasses the AI tailoring phase and instead uploads your *unaltered* Base Resume and Base Cover Letter to Google Drive. This ensures you still get valid application assets.

**LaTeX Compilation Fallback:**
LLMs occasionally generate unescaped LaTeX characters (like `&`, `%`, or `$`) in company names, which causes `pdflatex` to throw a fatal error. The script monitors the compiler's exit code. If compilation fails, the script abandons PDF generation and leaves the PDF link columns blank. However, it successfully writes the raw LaTeX code into the "Resume LaTeX Template" and "Cover Letter LaTeX Template" columns. You can then copy that code into Overleaf, fix the minor syntax error, and compile it manually.

**Google Sheets API Fallback:**
If Google's API limits are reached or a network outage occurs, the script serializes the completed data to a local `fallback_cache.csv` file on the GitHub runner. Because GitHub runners are ephemeral, the workflow uses the `actions/upload-artifact` action to save this CSV. On the next scheduled run at midday, the pipeline downloads the artifact, pushes the missed rows to the Google Sheet first, and then begins the new scrape.
